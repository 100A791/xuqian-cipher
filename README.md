# XUQIAN 加密站 / 许七安密匣

> 纯前端、浏览器本地完成的文件加密工具。文件与密钥**永不上传服务器**。
> 每次加密生成一把 **128 位主密钥**，**只展示一次**，关闭弹窗立即销毁，网站不保存、不上传、不提供任何后门。

- 加密输出统一使用 `.XUQIAN` 后缀（例如 `photo.jpg` → `photo.jpg.XUQIAN`）
- 主密钥可用 `.XUQIANKEY` 文件备份（支持密码保护）
- 支持 1~10 层多算法叠加，解密严格逆序
- **密钥丢失后无法恢复** —— 这是设计目标，不是缺陷

## 快速开始

### 环境要求

- Node.js ≥ 20.19（开发时使用 v24 验证）
- pnpm（或 npm / yarn）
- 现代浏览器（Chrome / Edge / Firefox / Safari 近两年版本）

### 本地运行

```bash
pnpm install

# HTTP 开发服务器（固定端口 5188，避免与其他服务冲突）
pnpm dev
# → http://127.0.0.1:5188/

# 如果想用 HTTPS 本地预览（需要本机 openssl）
pnpm dev:https
# → https://127.0.0.1:5443/
```

> Windows 用户可以直接双击项目根的 **`start-xuqian.bat`**：
> 自动检查 node / pnpm、缺依赖时自动安装、启动服务器并**自动打开浏览器**；
> 关闭弹出的"XUQIAN dev server"窗口即停止服务。同名 `start-xuqian.cmd` 是给旧快捷方式用的转发文件。

> 端口 3000 / 3080 / 3081 已被其他服务占用，本项目默认使用 **5188**（开发）与 **5189**（预览）。
> `localhost` 属于浏览器认可的安全上下文，`crypto.subtle`、Web Worker、剪贴板 API 均可正常使用。

### 构建与预览

```bash
pnpm build        # 类型检查 + 产出 dist/
pnpm preview      # 本地预览构建结果（5189）
```

产物体积（gzip 后约）：主包 ~136 KB；工具箱与自研路线按需加载（约 14 个 chunk），选「加密」的用户不下载它们。

### 全部验证（推荐）

```bash
pnpm test:all
# = 文档守卫 + 格式 + 类型 + 单元测试 + 构建 + CLI + 冒烟 + 文件头 + 互操作 + 离线壳
```

## 功能清单

### P0（核心，已全部实现）

| 功能 | 说明 |
| --- | --- |
| `.XUQIAN` 后缀 | 加密输出统一为 `原名.XUQIAN`；解密还原原文件名与格式 |
| 128 位主密钥 | 16 字节，Hex 32 字符 / Base64 24 字符 / SHA-256 前 8 字节指纹 |
| 一次性展示与销毁 | 加密后强制弹窗，红色警告，关闭即覆写销毁并二次确认 |
| 多种算法 | AES-128-GCM、AES-256-GCM、ChaCha20-Poly1305、XChaCha20-Poly1305、SM4-GCM |
| 多重加密 | 1~10 层，可自由排序；HKDF-SHA256 逐层派生独立子密钥 |
| 独立 nonce | 每层每块独立随机种子派生，绝不复用 |
| 逆序解密 | AEAD tag 校验，密钥错误或文件被篡改统一提示 |
| 零后端 | 纯静态，无任何网络请求（CSP 限制为同源） |

### P1（重要，已实现）

- 文本加密模式（密文为 `XUQIAN1:` 前缀的 Base64 串，也可存为 `.XUQIAN` 文本文件）
- 批量/文件夹加密：拖入整个文件夹保持目录结构，可打包为 ZIP
- 大文件分块加密 + 进度条（默认 64 MiB 分块，每块独立 nonce）
- 加密前 gzip 压缩，解密后自动解压
- **元数据加密（默认开启）**：原文件名 / MIME / 备注一并加密，拿到密文也读不出"这是什么文件"
- 密钥二维码（弹窗内生成，可下载 PNG，关闭弹窗即销毁）
- Shamir 密钥分片（2~10 份，任意 M 份恢复，含自检）
- 密码短语保护密钥文件（PBKDF2-SHA256 600,000 次 + AES-256-GCM）
- **口令强度实时评估**：设置密钥文件口令时给出熵估算与弱口令/模式警告
- **密钥轮换向导**：只换密钥文件口令、不重加密数据（主密钥与指纹不变）
- **空闲自动锁定**：无操作达设定时长或手动点「锁定」即销毁主密钥、清空明文
- 随机密码生成器（长度/大小写/数字/符号，CSPRNG）
- 哈希校验工具（SHA-256 / SHA-512，加密前记录、解密后自动比对）
- 暗色/亮色主题、中英双语、快捷键、本地操作日志（不含密钥）
- 命令行工具（`xuqian` / `cli/xuqian.ts`，与网页共用同一套字节实现，可互解）
- **PWA 离线壳**：构建产物预缓存进 Service Worker，断网也能打开并完成加解密；
  离线手册（docs/*.md 纯文本）一并预缓存；新版本在**关闭所有标签页后**生效，
  出现「发现新版本」横幅时点击刷新即可（未备份的密钥会先经确认框保护）
- **离开页面前确认**：密钥尚未销毁时刷新/关闭会先弹浏览器确认框（误按 F5 的代价不可逆）
- **时间锁（基于时间戳验证）**：加密时可设「生效时间」与「到期时间」——解密端在解开 meta 之后、
  解出任何明文之前用本机时间戳校验，窗口外直接拒绝（CLI 同规则）。如实说明：验证基于本机时钟，
  改系统时间可绕过，定位是"防手滑 + 跨设备约定"，不是"防对抗"

## 使用指南

### 加密文件

1. 打开「加密」标签页
2. 拖入文件或文件夹（拖文件夹会保持目录结构）
3. 选择算法层数与顺序（列表自上而下显示，**自下而上执行**，例如列表中自上而下是
   `SM4-GCM / ChaCha20-Poly1305 / AES-256-GCM`，实际加密顺序就是
   `AES-256-GCM → ChaCha20-Poly1305 → SM4-GCM`）
4. 可选：勾选 gzip 压缩、填写备注、设置到期提醒时间
5. 可选：**保持「加密元数据」勾选**（默认开），把原文件名 / MIME / 备注一并加密
6. 点击「开始加密」
7. **必须在密钥弹窗中复制或下载密钥**，然后点击「我已复制，关闭并销毁」
8. 下载 `.XUQIAN` 文件（多个文件可一键打包 ZIP）

> 批量加密共用同一把主密钥，因此**只会弹出一次**密钥弹窗。

> 顶栏有一个「锁定」按钮：点一下即销毁主密钥并清空已解出的明文；此外可在
> 「工具 → 设置」里配置**空闲自动锁定**（默认 5 分钟，可关闭）。

### 解密文件

1. 打开「解密」标签页，拖入 `.XUQIAN` 文件
2. 输入 128 位密钥，或上传 `.XUQIANKEY` 文件（若设置了密码需一并输入）
3. 点击「开始解密」
4. 解密完成后网站自动：校验 SHA-256 → 提示结果 → **清除内存中的密钥与子密钥**
5. 下载还原后的原文件

> 网站**不会**自动填充任何历史密钥，也不会保存你输入过的密钥。

### 密钥分片（Shamir）

在密钥弹窗中设置 M（至少需要几份）与 N（共分成几份），点击「生成分片」。
生成后点击「下载全部分片」会得到一个文本文件，内含 N 行分片文本。

恢复方式：打开「工具」标签页 → 「分片恢复密钥」，每行粘贴一份分片（至少 M 份），
点击「恢复密钥」即可得到主密钥，并自动下载对应的 `.XUQIANKEY` 文件。

> 分片等价于主密钥的一部分，请分发给不同保管人，切勿集中存放。

### 密钥轮换（更换密钥文件口令）

「工具」标签页 → 「密钥轮换」：选择 `.XUQIANKEY` → 填当前口令 → 填新口令（会实时显示强度）
→ 点「生成新密钥文件」。

**只重封装密钥文件，不重加密数据**：主密钥不变，已有 `.XUQIAN` 文件继续可用，指纹也不变。
旧口令对新文件立即失效。

> 注意：若泄露的是**主密钥本身**（而不只是口令），轮换口令没有用——必须用新主密钥重新加密文件。

### 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `1` / `2` / `3` / `4` | 切换加密 / 解密 / 文本 / 工具 |
| `Esc` | 关闭弹窗 / 返回加密页 |
| `Ctrl+Shift+L` | 切换亮色/暗色主题 |

## 安全模型

完整说明见 [`docs/SECURITY.md`](docs/SECURITY.md)，这里给出要点。

### 做对了什么

1. **密钥不出浏览器**：所有加解密在 Web Worker 内完成，主线程从不长期持有密钥对象。
2. **一次性展示**：展示文本只在弹窗打开期间存在，关闭时调用 `key-destroy` 命令
   Worker 覆写主密钥字节并释放引用。
3. **不落盘**：密钥绝不写入 localStorage / sessionStorage / IndexedDB / Cookie / URL / 日志 / 服务器。
   自动化测试会逐项断言这一点。
4. **不提供找回**：代码中不存在任何"恢复历史密钥"的路径；刷新或关闭页面即彻底丢失。
5. **标准算法**：AES-GCM 走 WebCrypto（硬件加速），ChaCha20/XChaCha20 用 `@noble/ciphers`；
   SM4 为 GB/T 32907-2016 标准实现，采用 NIST SP 800-38D 的标准 GCM 组合，未自创算法。
6. **头部认证**：文件名、时间、哈希、备注等元数据全部纳入 AEAD 的 AAD，改一个字节即解密失败。
7. **元数据也加密**（简单路线默认开启）：原文件名 / MIME / 备注收进 `meta.x`（AES-256-GCM，密钥由主密钥派生），
   拿到密文但没有密钥的人连"这是什么文件"都看不到——文件名本身常常就泄密。
8. **会话可锁定**：空闲达设定时长或手动点「锁定」即销毁主密钥、清空一次性密钥视图与已解出明文。
9. **统一错误**：密钥错误与文件损坏都返回同一个提示，不泄露 oracle 信息。
10. **离线壳不碰数据**：Service Worker 只预缓存构建产物（HTML / JS / CSS / 图标），
    不缓存用户文件、明文或密钥；密钥仍然只在 Worker 的内存里。缓存可在浏览器站点设置里单独清除。

### 必须知道的边界（诚实披露）

- **JavaScript 字符串无法擦除**。密钥的 Hex/Base64 文本副本在弹窗关闭后只能等待 GC 回收，
  无法像 `Uint8Array` 那样主动覆写。这是语言层面的限制，任何纯前端方案都无法规避。
  本项目通过"权威密钥只在 Worker 的 TypedArray 中、文本副本仅在弹窗期间存在"把窗口压到最小。
- **浏览器扩展 / 恶意脚本**：若你用此网站时浏览器里存在恶意扩展或 XSS，密钥可能被窃取。
  建议使用独立浏览器配置、无扩展模式，并在离线或可信网络下操作。
- **剪贴板**：复制密钥后，剪贴板中的内容可能被其他程序读取。设置中可开启"10 秒后尝试清空剪贴板"
  （浏览器要求页面保持聚焦才能写入）。
- **本地文件系统**：下载的 `.XUQIAN` 与 `.XUQIANKEY` 都在你的磁盘上，请自行做好离线备份与物理安全。
- **纯前端不能强制自毁**：到期提醒只是写入文件头的提示，无法阻止持有密钥的人解密。
- **自研加密路线（`src/selfcrypto/`）的定位是"算法完全可审计"，不是"更安全"**：
  它零第三方依赖、算法全部自己实现，但因此**不享受硬件加速与常数时间实现**——
  查表型 AES 存在 cache-timing 侧信道、实测约 2 MB/s 单向、不提供口令加密（主密钥丢失即**永久不可恢复**）。
  **保护真正敏感的数据请优先用「简单加密」路线。** 逐条边界见
  [`src/selfcrypto/README.md`](src/selfcrypto/README.md) §8 与 [`docs/SECURITY.md`](docs/SECURITY.md)「自研加密路线的已知边界」。

## 部署

纯静态站点，`dist/` 可直接托管到任意静态平台：

```bash
pnpm build
# 上传 dist/ 到 Vercel / Cloudflare Pages / Netlify / Nginx / 对象存储
```

> 用「发布应用」发布在线链接时，先 `pnpm site:sync` 把 `dist/` 同步到 `publish/` 再发布
> ——不要直接发布 `dist/`：构建会清空它，连同样式已发布应用的记录一起清掉。

### 部署清单

- [ ] **启用 HTTPS**（必需：`crypto.subtle` 与 Worker 仅在安全上下文可用）
- [ ] 保留 `index.html` 中的 CSP 头（已限制为 `default-src 'none'`，只允许同源自身资源）
- [ ] 建议追加安全响应头：
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: no-referrer`
  - `Permissions-Policy: geolocation=(), camera=(), microphone=()`
- [ ] 若需要浏览器端 gzip 解压的 WASM 变体，确认 `Content-Type` 正确
- [ ] **PWA**：`dist/` 已含 `sw.js` / `manifest.webmanifest` / `icons/`，HTTPS 下可安装；
      不要给 `sw.js` 设长期缓存（建议 `Cache-Control: no-cache`），否则更新会被延迟
- [ ] **不要**接入任何会记录请求体的日志/CDN 分析脚本（虽然本站不发送任何请求，
      但第三方脚本会破坏 CSP，也会引入 XSS 风险）

## 常见问题

**Q：忘记保存密钥了，能找回来吗？**
不能。这是设计目标。唯一办法是用原文件重新加密一次并生成新密钥。
网站没有、也不会有任何"密钥找回"入口。

**Q：为什么解密失败只提示"密钥错误或文件损坏"？**
为了不泄露加密预言机（oracle）信息。区分"密钥错"与"文件被改"会帮助攻击者逐步试探，
因此我们统一返回同一个错误。

**Q：`.XUQIAN` 文件头是明文，安全吗？**
头部只包含算法、层数、salt、nonce、原始文件名/哈希/时间等**非机密**信息，
不含任何密钥材料。这些字段全部参与 AEAD 认证，被篡改会导致解密失败（头部还有 CRC32 校验）。
如果你不想暴露原文件名，可以在加密前重命名文件，或使用文本模式。

**Q：多层加密会让文件变得多安全？**
多层是"纵深防御"：即使某一层算法未来被攻破，其余层仍然保护数据。
但请注意，**安全性主要由密钥强度与保管方式决定**，而不是层数。
层数过多只会让加解密变慢、文件略大。

**Q：支持多大的文件？**
理论上受浏览器内存限制。分块加密让单块占用有界（默认 64 MiB），
但最终文件对象仍在内存中组装，实践建议单文件 < 1 GiB。
极大文件请改用等价的命令行工具（P2 规划中）。

**Q：密钥弹窗关了但文件还没下载完怎么办？**
解密不受影响（解密只需要密钥）。但如果加密输出还没保存，可以重新加密一次。
密钥销毁只影响"再次查看密钥"，不会删除已生成的 `.XUQIAN` 文件。

**Q：网站会记录我的操作吗？**
「工具」页有一个本地日志，只存在你自己的 `localStorage` 里，写入前会用正则过滤疑似密钥的
长串，且永远不会上传。你可以随时清空。
