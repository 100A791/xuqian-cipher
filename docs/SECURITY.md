# 安全模型与风险提示

本文档说明「XUQIAN 加密站 / 许七安密匣」做了什么、**没做什么**，以及你必须自行承担的风险。
所有结论都可以在源码中核对，并可用 `pnpm test:all` 复现。

---

## 一、安全目标

1. 文件内容在离开浏览器前已经加密；网站**不发送任何网络请求**。
2. 主密钥只在用户浏览器内生成，**只展示一次**，关闭弹窗后立即销毁。
3. 网站不保存、不上传密钥或文件，**不提供任何找回机制**。
4. 密钥错误与文件被篡改时，对外表现完全一致（不泄露 oracle）。
5. 不发明加密算法；全部使用标准算法与成熟实现。
6. **元数据同等级保护**（简单路线默认开启）：原文件名 / MIME / 备注等标识性字段也加密，拿到密文但没有密钥的人连"这是什么文件"都读不到。
7. **会话可锁定**：空闲达设定时长或手动点「锁定」即销毁主密钥、清空已解出的明文。

## 二、威胁模型

### 2.1 防御的威胁

| 威胁 | 防御手段 |
| --- | --- |
| 服务器/托管方窃取文件 | 加密在浏览器完成，密文才离开本地；无可上传的明文 |
| 传输过程被监听 | 加密数据本身即密文；部署要求 HTTPS |
| **从密文推断文件内容/名称** | **元数据加密**：原文件名 / MIME / 备注等收进 `meta.x`（AES-256-GCM，密钥由主密钥派生），没有密钥读不出 |
| **离开工位后被旁人操作/窥屏** | **空闲自动锁定** + 手动「锁定」：销毁主密钥、清空已解出明文与一次性密钥视图（默认 5 分钟） |
| **口令过弱被离线爆破** | 设置密钥文件口令时实时评估强度（熵估算 + 弱口令/模式识别）并给出明确警告 |
| 中间人篡改密文或文件头 | 头部全部纳入 AEAD 的 AAD + CRC32；篡改即解密失败 |
| 密文被离线暴力破解 | 128 位密钥 + 标准 AEAD；密钥空间 2^128 |
| 密钥错误导致误解 | 只提示"密钥错误或文件损坏"；指纹供人工比对 |
| 加密后忘记备份密钥 | 弹窗强制展示 + 红色警告 + 未复制/未下载时二次确认 |
| 通过浏览器存储复原密钥 | 密钥不写入 localStorage/sessionStorage/IndexedDB/Cookie/URL |
| 通过日志泄露密钥 | 日志写入前正则过滤长 Hex/Base64 串 |

### 2.2 **不**防御的威胁（重要）

| 威胁 | 说明 | 缓解建议 |
| --- | --- | --- |
| 恶意浏览器扩展 | 扩展可以读取页面 DOM 与剪贴板，包括弹窗里的密钥 | 使用无扩展的独立浏览器配置 |
| 本机恶意软件 / 键盘记录 | 可记录你输入的密钥与剪贴板内容 | 使用干净的离线设备 |
| XSS 注入 | 若站点被注入脚本，密钥可被窃取 | 已设置严格 CSP；不要引入第三方脚本 |
| 物理访问 | 磁盘上的 `.XUQIANKEY` 就是密钥 | 离线保存、加密磁盘、分离存放 |
| 密码被暴力破解 | `.XUQIANKEY` 的密码保护依赖 PBKDF2 600k | 使用高熵长密码（≥ 16 位随机） |
| 分片被集中窃取 | 任意 M 份即可恢复 | 分片分发给不同保管人，物理分离 |
| 纯前端强制自毁 | 到期提醒只是头部提示 | 不要把"到期"当作安全控制 |
| **空闲锁定被绕过** | 锁定只是"缩短暴露窗口"的界面措施，不改变密码学保证；恶意扩展/本机程序仍可读屏 | 离开时手动锁定 + 系统锁屏 + 干净设备 |
| **「时间戳附加盐」被当成安全措施** | 时间戳必须明文存入文件头，**公开的低熵盐不提供任何机密性**，也不增加爆破成本 | 不要依赖它；密钥强度只来自 CSPRNG 随机或高熵口令 |
| **换设备 / 清浏览器数据** | 站点不保存任何密钥；密钥文件丢失且无备份即不可恢复 | 离线多处备份 `.XUQIANKEY`；轮换口令时主密钥不变，指纹可用于核验 |
| 大型文件的可用性 | 受浏览器内存限制 | 超大文件请用命令行工具（P2） |

## 三、密钥生命周期（本项目最关键的安全设计）

### 3.1 存储位置

```
主密钥权威副本：crypto.worker.ts 内的 `let masterKey: MasterKey | null`
              （Uint8Array 承载，可被 fill(0) 覆写）
主线程：       仅在"密钥弹窗打开期间"持有一次性的 Hex/Base64 文本视图
持久化：       无（localStorage / sessionStorage / IndexedDB / Cookie / URL 全部不写入）
```

主线程通过 `postMessage` 与 Worker 通信；主密钥**从不**以可传递对象的形式离开 Worker。

### 3.2 时间线

```
1. 用户点击「开始加密」
2. client.generateKey()  →  Worker 内 MasterKey.generate()（CSPRNG）
3. 加密过程中，主密钥仅用于派生与逐层加密
4. 加密完成 → client.viewKey() 取一次性文本视图 → 弹出密钥弹窗
5. 用户操作：
     复制 Hex / 复制 Base64  → 标记为已复制（可选的 10 秒剪贴板清理）
     下载 .XUQIANKEY        → 标记为已下载
     生成 Shamir 分片        → 仅在内存中生成并即时下载
6. 用户点击「我已复制，关闭并销毁」
     ├─ 若既未复制也未下载 → 先弹出二次确认
     └─ 确认后执行 finalizeClose()
          · destroyedRef = true（幂等，防重复销毁）
          · cryptoClient.destroyKeySync()  →  Worker 覆写主密钥字节并置 null
          · closeKeyModal()                →  一次性文本视图置 null，弹窗卸载
          · 记录一条不含密钥的日志
7. 再次点击加密 → 生成全新密钥（旧密钥已不可恢复）
```

`destroyKeySync()` 与 `destroyKey()` 都会把 `#keyPresent` 置为 `false`；
此后任何 `viewKey()` 调用都会失败（Worker 返回 `KEY_NOT_AVAILABLE`）。

### 3.3 刷新/关闭页面

- `pagehide` 与 `beforeunload` 事件会立即发送 `key-destroy`
- 即使消息未送达，浏览器也会销毁整个 Worker 及其内存
- 刷新后不存在任何持久化数据可以恢复密钥

### 3.4 诚实披露：JavaScript 的固有限制

**字符串不可擦除。** 密钥的 Hex/Base64 文本视图一旦生成，就无法主动覆写，
只能等待垃圾回收。本项目无法绕开这一语言限制，只能把这类副本的生存期压到最短：

- 文本视图**只在弹窗打开期间**存在
- 关闭弹窗时立即把 store 中的引用置为 `null` 并卸载 DOM
- 弹窗内所有次要状态（密码、分片、二维码等）一并清空

任何声称"纯前端可以彻底擦除内存中的密钥字符串"的说法都是不准确的。

### 3.5 口令轮换（密钥轮换向导）

怀疑密钥文件口令泄露时，可在「工具箱 → 密钥轮换」换一个口令。**只重封装密钥文件，不重加密数据**：

```
旧文件 --(旧口令 PBKDF2 解出)--> innerJson --(新口令 PBKDF2 重新封装)--> 新文件
```

- 主密钥本身**不变**，因此已有 `.XUQIAN` 文件继续可用，无需重加密。
- 指纹保持不变，便于核验"换的是同一把密钥"。
- 旧口令对新文件立即失效。
- 轮换在**本地**完成，主密钥不需要导入运行中的会话。

这也意味着：**已泄露的旧主密钥本身仍然有效**。若主密钥（而非仅口令）已泄露，正确做法是用**新主密钥重新加密文件**，不能只轮换口令。

## 四、密码学实现说明

| 用途 | 算法 | 实现来源 | 备注 |
| --- | --- | --- | --- |
| 对称加密（AES） | AES-128/256-GCM | WebCrypto（主）/ `@noble/ciphers`（后备） | 12 字节 nonce，128 位 tag |
| 对称加密（ChaCha） | ChaCha20-Poly1305 / XChaCha20-Poly1305 | `@noble/ciphers` 2.4.0 | RFC 8439 / IRTF draft |
| 对称加密（国密） | SM4-GCM | 本项目 `src/crypto/sm4.ts` | GB/T 32907-2016 分组密码 + NIST SP 800-38D 的 GCM 组合 |
| 密钥派生 | HKDF-SHA256 | `@noble/hashes` 2.4.0 | 每层独立 salt，info 绑定层号与算法；可选并入时间戳做域分离 |
| 元数据加密 | AES-256-GCM | WebCrypto（主）/ `@noble/ciphers`（后备） | 密钥 MEK 由主密钥 HKDF 派生（`XUQIAN/v1/meta`），加密 `meta.x` |
| 密码派生 | PBKDF2-SHA256 | WebCrypto | 600,000 次迭代 |
| 摘要 | SHA-256 / SHA-512 | WebCrypto / `@noble/hashes` | 文件哈希与指纹 |
| 随机数 | `crypto.getRandomValues` | 浏览器 CSPRNG | 主密钥、salt、nonce 种子、Shamir 系数、密码生成器 |
| 门限共享 | Shamir over GF(2^8) | 本项目 `src/crypto/shamir.ts` | 1979 年公开方案，AES 同款不可约多项式 |

### 关于 SM4-GCM 的说明

SM4 是公开的国家标准分组密码；GCM 是公开的 NIST 认证加密模式。
本项目把二者按标准方式组合（CTR 加密 + GHASH 认证），**没有发明任何密码学构造**。
该实现经过 GB/T 32907-2016 官方测试向量验证（见单元测试）。

同时必须承认：这是一份**可审计优先、性能次优**的纯 JavaScript 实现，
运行在共享环境中的常量时间性不如原生实现。默认场景推荐使用 AES-GCM
（走 WebCrypto 硬件加速）或 ChaCha20-Poly1305。

### 自研加密路线（`src/selfcrypto/`）的已知边界

本站除了上面的「简单加密」，还提供一条**零第三方依赖、算法全部自研**的路线。
它的取舍与简单路线**正好相反**：不依赖任何库（便于完整审计），代价是安全性上限更低。
以下边界如实列出（完整版见 [`selfcrypto/README.md`](../src/selfcrypto/README.md) §8）：

| 边界 | 说明 | 建议 |
| --- | --- | --- |
| **查表型 cache-timing 侧信道** | AES 的字节代换是查表实现（`SBOX[b]`），索引同时依赖密钥与数据。在共享 CPU（云桌面、多租户虚拟机）上是真实攻击面。**范围需说清**：表只有 256 字节 S 盒（约 4 条缓存行），**没有**经典 1 KB T 表；`mixColumns` 是常数时间的（固定 8 次迭代的 `gfMul`，不查表）—— 这正是它只有约 2 MB/s 的原因，慢是常数时间的代价 | 侧信道敏感场景请用简单路线（WebCrypto，常数时间 + 硬件加速） |
| **KEY_CHECK 是可离线验证的明文预言机** | 密钥确认值明文写在文件头偏移 77，**只拿 97 字节文件头**即可验证任意密钥猜测，无需文件主体、无需触碰解密 | 对随机 128 位主密钥无影响；若将来接入口令模式需重新评估 |
| **段拆分/重排不提供机密性** | 其参数（段数 / 顺序 / 拆分方式 / 分块）全部明文在头部，是**公开可逆的字节置换** | 已在文档中明确不声称任何安全收益 |
| **不提供口令加密** | PBKDF2 已实现且通过全部向量，但**未接入加密流程**；主密钥是唯一凭据，**丢失即永久不可恢复** | 需要"可回忆的口令"请用简单路线（支持 PBKDF2 口令导出与轮换） |
| **纯 JS 性能** | 实测约 1.8~2.0 MB/s 单向（1 GB 需 8~9 分钟） | 大文件请用简单路线 |
| 主密钥 128 位 | AES-128-CTR（`MASTER_KEY_LEN = 16`） | 长期归档可考虑简单路线的 AES-256 |

**一句话**：自研路线的定位是"**算法完全可审计**"，不是"更安全"。
保护真正敏感的数据时，请优先使用「简单加密」路线。

## 五、错误处理策略

对外只暴露三类结果：

| 用户看到的提示 | 触发条件 |
| --- | --- |
| **密钥错误或文件损坏** | 任何 AEAD 认证失败（`AUTH_FAILED`） |
| **不是有效的 .XUQIAN 文件，或文件已被截断** | 魔数/版本/头部 CRC/长度校验失败 |
| **当前没有可用密钥** | 密钥已销毁或尚未导入 |

内部错误码（如 `HEADER_CRC_MISMATCH`、`TAG_TRUNCATED`、`CHUNK_LAYOUT_INVALID`）
**不会**呈现给用户，避免攻击者用错误信息区分失败原因（padding/authentication oracle）。

## 六、CSP 与部署加固

`index.html` 中已内置：

```
default-src 'none';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
font-src 'self' data:;
connect-src 'self';
worker-src 'self' blob:;
manifest-src 'self';
base-uri 'none';
form-action 'none'
```

含义：页面**无法**发起任何跨域请求，无法加载第三方脚本。
若你需要接入分析或 CDN，必须修改 CSP —— 那会削弱以上保证，请谨慎评估。

> **点击劫持（iframe 嵌套）防护：当前未由本站提供。**
> `frame-ancestors` 是**响应头专属**指令，写在 `<meta>` 里浏览器会直接忽略（控制台会提示
> "The Content Security Policy directive 'frame-ancestors' is ignored when delivered via a <meta> element"）。
> 本站是纯静态站点，页面自身无法设置响应头，所以此前写在 meta 里的 `frame-ancestors 'none'`
> **并没有真正生效**，已从 meta 中移除以免造成虚假安全感。需要该防护时，请在托管侧加：
> `Content-Security-Policy: frame-ancestors 'none'` 或 `X-Frame-Options: DENY`。

建议在 Web 服务器追加的响应头见 [README 部署清单](../README.md#部署)。

## 七、剪贴板与二维码

- 复制密钥后可开启「10 秒后尝试清空剪贴板」。浏览器要求在页面保持聚焦时才能写剪贴板，
  因此该操作可能失败（失败时静默，不影响密钥安全）。
- 二维码内容为 `XUQIANKEY:<hex>:<fingerprint>`，**等同于密钥本身**。
  界面已明确提示不要截图外传；二维码 canvas 在弹窗关闭时随 DOM 一起销毁。
- 剪贴板可能被其他程序读取，这是操作系统的既有行为，本网站无法控制。

## 八、隐私声明

- 本网站**没有后端**，`connect-src 'self'` 禁止任何外发请求。
- 不上传文件、不上传密钥、不上传日志、不使用第三方分析。
- 仅使用 `localStorage` 保存若干非敏感设置：主题、语言、剪贴板清理开关、**是否加密元数据**、**空闲自动锁定分钟数**；
  以及一个本地操作日志（可随时清空，写入前会过滤长密钥串）。
- 清除浏览器数据即可抹除上述全部内容。
