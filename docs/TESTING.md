# 测试用例与验收标准

本文档列出全部测试用例、如何运行，以及需求文档「十、验收标准」的逐条对照。

---

## 一、如何运行

```bash
pnpm typecheck     # TypeScript 严格模式类型检查
pnpm test          # Vitest 单元测试（66 项）
pnpm build         # 类型检查 + 生产构建
pnpm dev           # 另开终端：启动 http://127.0.0.1:5188/
pnpm test:cli      # 命令行工具测试（55 项，含与网站共用加密实现的往返）
pnpm test:smoke    # 浏览器端到端冒烟测试（119 项，真实 Edge/Chrome + CDP，含 11 处无障碍审计）
pnpm test:header   # .XUQIAN 文件头结构验证（真实落盘文件解析）
pnpm test:interop  # 浏览器 ↔ 命令行 双向互操作（27 项）
pnpm test:selfcrypto  # **自研加密路线**（15 套 227 项断言，零依赖运行器）
pnpm bench         # 性能基准（实测数字，写入 docs/PERFORMANCE.md）

pnpm test:all      # 以上全部（推荐在交付前执行）
```

冒烟测试会自动探测本机 Edge / Chrome 的安装路径，使用 `--headless=new` 启动，
不依赖 Playwright 等额外依赖。若未找到浏览器，脚本以退出码 2 表示"跳过"。

## 二·补、自研加密路线（`tests/unit/`，15 套 227 项断言）

自研路线不依赖 Vitest/任何第三方，用自带的零依赖运行器：

```bash
pnpm test:selfcrypto     # 等价于 node tests/unit/run-all.js
```

| 套件 | 项数 | 验什么 |
| --- | --- | --- |
| `test_random` | 7 | CSPRNG 封装：长度校验、`randomUint32` **32 位完整性回归**（曾退化成 8 位）、`randomInt` 闭区间与无取模偏置 |
| `test_sha256` | 18 | FIPS 180-4 向量 + 边界（空串 / 分块填充） |
| `test_hmac` | 14 | RFC 4231 向量 |
| `test_pbkdf2` | 10 | OpenSSL 交叉生成的 PBKDF2-HMAC-SHA256 向量 |
| `test_aes` | 12 | FIPS 197 单块（含 S 盒逐项） |
| `test_ctr` | 14 | NIST SP 800-38A |
| `test_format` | 13 | 97 字节头部逐字段偏移、KV 帧的 8 类非法输入、长度自洽 |
| `test_file_crypto` | 18 | 往返 + **与 OpenSSL 双向交叉验证** + 6 类篡改 + 错密钥 + 截断 |
| `test_watermark` | 29 | LSB 位置序列 / 公开层 / 私有层 / 有形水印两种 mode（角落 + 全图平铺） |
| `test_ai_detect` | 45 | 元数据四容器（JPEG/PNG/WebP/HEIC-AVIF）+ DCT/FFT/DWT 三种变换的正确性 |
| `test_storage` | 19 | 密文库"无密钥字段"白名单 + 整库备份往返 + **SPEC 目录结构与禁止事项的机械校验** |
| `test_large_file` | 7 | 12 MB / 12 块完整性、分块边界（1 块 ±1 字节）、块间计数器不重叠 |
| `test_interrupt` | 8 | 17 处截断横扫 / 追加 / 全零 / 头部篡改 —— 全部统一失败且不返回部分明文 |
| `test_uniform_delay` | 7 | **实测**失败耗时落在 4~5 秒（错误密钥 4023ms / 篡改 4118ms） |
| `test_progress` | 6 | 分阶段进度回调：阶段序列、块计数单调、失败路径不上报解密阶段 |

**为什么这些断言可信**：向量不是手抄的，由 `tools/gen_vectors.js` 用 `node:crypto`（OpenSSL）算出；
FFT 额外与朴素 DFT（O(N²) 独立实现）逐点对照；DWT 用正交归一化的能量守恒验证。
**只做自测是不够的**——"段重排要按长度切分"这个 bug 就是往返测试全绿、交叉验证才暴露的。

## 三、端到端冒烟测试（`scripts/smoke.mjs`，119 项）

真实浏览器执行，覆盖完整用户路径。**跑之前会先清掉遗留的浏览器进程**——被中断的运行会留下实例，
导致下一次连到旧页面并静默挂死（本机踩过两次：一次累积 12 个进程、一次 33 个）：

### 3.1 文档可达性（回归：`docs/` 曾未被开发服务器托管，浏览器打开 404）

1. 7 篇文档全部可访问且非空：`/docs/index.html`、`GUIDE.md`、`FORMAT.md`、`SECURITY.md`、
   `TESTING.md`、`KEY-LIFECYCLE.md`、`README.md`
2. 手册内 **22 张截图**链接全部有效（逐张 `fetch` 校验）
3. 应用头部「文档」入口存在，且指向 `./docs/index.html`

> 另有构建期校验 `scripts/sync-docs.mjs`：检查 Markdown 相对链接是否指向真实文件、
> 是否残留非 ASCII 锚点（中文标题锚点在多数渲染器里失效），失败即中止构建。

### 3.2 页面与框架

4. 页面挂载成功（React 渲染出内容）
5. 品牌标题正确（包含 `XUQIAN`）
6. 四个主 Tab 存在（加密/解密/文本/工具）

### 3.3 密钥一次性展示（对应验收 13–15）

7. 加密后**自动**弹出密钥弹窗
8. 弹窗含"只显示这一次 / 关闭即销毁 / 无法再次查看"红色警告
9. Hex 为 32 字符
10. Base64 为 24 字符
11. 展示 16 位 Hex 指纹
12. 弹窗打开时密钥默认被选中
13. 弹窗内二维码已渲染（canvas 像素校验）
14. 未复制未下载时关闭 → 弹出二次确认
15. 取消后弹窗保持打开且密钥仍在
16. 可下载 `.XUQIANKEY` 密钥文件
17. 关闭后弹窗 DOM 卸载

### 3.4 零残留（对应验收 16–18）

18. localStorage 中无密钥
19. sessionStorage 中无密钥
20. Cookie 中无密钥
21. URL 中无密钥

24. 刷新后 localStorage/sessionStorage 中无密钥
25. 刷新后页面文本无密钥

### 3.5 文本加解密（对应验收 3、6、9）

26. 文本密文已生成（`XUQIAN1:` 前缀）
27. 错误密钥 → 提示"密钥错误或文件损坏"
28. 正确密钥 → 解密成功且内容一致
29. 解密后自动做 SHA-256 校验并提示一致

### 3.6 真实文件往返（P0 核心）

对三种文件各跑一遍完整的"加密 → 下载 → 解密 → 下载 → 字节比对"：

| 文件 | 大小 | 层数 | 算法 | 附加 |
| --- | --- | --- | --- | --- |
| `photo.jpg` | 150,000 B | 1 | AES-128-GCM | — |
| `notes.txt` | 4,096 B | 2 | ChaCha20-Poly1305 + … | 多层 |
| `empty.bin` | 0 B | 1 | AES-256-GCM | 空文件边界 |

每个文件断言：
30. 每次加密生成不同的 128 位密钥
31. 关闭密钥弹窗成功（含多文件场景，验证弹窗状态正确复位）
32. 加密输出以 `.XUQIAN` 结尾
33. 文件真实下载到磁盘
34. 解密后文件与原文件**字节级一致**
35. 解密还原原文件名

### 3.7 用 `.XUQIANKEY` 解密（含密码保护，时序回归）

36. 生成密码保护的 `.XUQIANKEY`（`protected: true`）
37. **上传 `.XUQIANKEY` 后不等待、不重渲染，立刻填密码点解密 → 必须成功**
    （这是用户反馈"老是解密失败"的根因回归项，见 `docs/KEY-LIFECYCLE.md` 第 2.4 节缺陷 3）
38. 密钥文件解密后字节一致
39. 密钥文件解密还原原文件名
40. 错误密码 → 统一提示"密码错误或密钥文件损坏"

### 3.8 交互与响应式（对应验收 10）

41. 亮色/暗色主题可切换
42. 移动端视口（390×844）无横向溢出

### 3.9 自研路线的真实链路（真上传文件、真 IndexedDB、真 Worker）

43. 自研主页五个入口齐备；五个页面都能独立打开
44. 加密页真上传文件 → 真出 128 位密钥；大文件按 1.5 MB/s 保守值提示预计耗时
45. 解密页对非密文给出**统一的「解密失败」**，且不泄漏失败原因
46. 水印页真嵌入 PNG → 出 WK；对有/无水印的图分别给出正确结论
47. **真浏览器量化**：角落水印只动 797 像素且全在右下角；全图平铺动 159949 像素、四象限均衡（40143/39969/39626/40211）；纯 LSB 层最大通道变化 ≤ 1
48. AI 检测页输出两栏报告，且恒带"未标定、不能作为结论"
49. **整库备份**：导出 → 清库 → 导入 → 恢复（含中文文件名），恢复后仍无密钥字段
50. 大文件加密期间主线程仍能响应（进度条数值被反复读到），并且可取消

### 3.10 无障碍审计（11 处页面）
51. 开始页、简单路线四页、自研路线六页各跑一遍，检查：`html lang`、图片 `alt`、
    控件可访问名、正 `tabindex`、标题层级不跳跃、`progressbar` 的 ARIA 自洽。
    **共查 160 个控件，0 违规**（修掉了 `Field` 组件没把 label 与控件程序化关联这个全站性缺陷）。
    **不覆盖颜色对比度**——需要渲染样式计算、容易假阳性，故不做，也不用"通过"暗示它没问题。

### 3.11 测试脚本的**安全红线**：不许按进程名杀浏览器

**事故记录（2026-10-05）**：冒烟脚本最初用 `taskkill /F /IM msedge.exe` 清理遗留测试实例，
那是**按进程名无差别杀** —— 结果反复把用户自己正在用的 Edge 窗口一起关掉了
（查证时用户开着 14 个 msedge 进程、旧写法会全部命中）。这不是"测试有点吵"，是**毁掉别人的浏览会话**。

**现行规则（`killStrayBrowsers`）**：两个条件**同时**满足才杀 ——
① 命令行含 `--headless`；② 命令行含我们自己的临时 profile 标记 `xuqian-smoke`。
拿不准就**什么都不杀**：宁可这次测试因为旧实例失败（可重跑），也不误伤用户的浏览器。

实测（用户 Edge 开着 14 个进程时）：新写法命中 **0** 个，旧写法命中 **14** 个。

推论到一般情形：**任何"清理环境"的动作都必须限定在自己创建的实体上**，按名字/按类型一刀切迟早会伤到用户的东西。

## 四、文件头结构验证（`scripts/verify-header.mjs`）

在真实浏览器里加密一个 **3 层 + gzip** 的 3000 字节文件（文件名含中文），
落盘后由 Node 直接解析 `.XUQIAN` 字节，断言：

| 断言 | 期望 |
| --- | --- |
| 魔数 | `XUQIAN` |
| 版本 | `1` |
| flags | 含 gzip 位（`0x02`） |
| chunkCount | `1` |
| layerCount | `3` |
| 算法顺序 | 等于 UI 层列表的**逆序**（UI 自上而下显示、自下而上执行） |
| 算法集合 | 与所选一致 |
| 原始文件名 | 完整保留中文（`report-报告.pdf`） |
| 原始大小 | `os = 3000` |
| gzip 生效 | `meta.s`（305）< `meta.os`（3000） |
| SHA-256 | 64 位大写 Hex |
| **密钥泄露检查** | 文件头字节中**绝不包含**主密钥 Hex |

实测输出示例：

```
magic          : XUQIAN
version        : 1
flags          : 2 (gzip=on)
chunkSize      : 67108864
chunkCount     : 1
layerCount     : 3
headerJsonLen  : 493
算法顺序        : SM4-GCM -> CHACHA20-POLY1305 -> AES-256-GCM
原始文件名      : report-报告.pdf
原始大小        : 305 (+os=3000)
SHA-256        : 614FA9F89832503A2932950D80D603ED5BEE0F3E060C94FD5CC1A4FE18CDC0E4
文件总大小      : 899
```

| 15 | 未复制或未下载时关闭必须二次确认 | ✅ | 冒烟 11/12 |
| 16 | 关闭弹窗后网站内无法再次查看密钥 | ✅ | 冒烟 20；`destroyKeySync` 后 `viewKey()` 失败 |
| 17 | 关闭后 localStorage/sessionStorage/IndexedDB/Cookie 无密钥 | ✅ | 冒烟 15–19 |
| 18 | 刷新页面后密钥不存在 | ✅ | 冒烟 21/22 |
| 19 | 解密完成后内存中的密钥被清除 | ✅ | `DecryptTab.runDecryption` 的 `finally` 调用 `cryptoClient.destroyKey()` |
| 20 | 网站不提供任何密钥找回功能 | ✅ | 代码中不存在历史密钥存储；`KeyModal` 关闭即清空视图 |

## 六、已知限制与未覆盖项

| 项 | 说明 |
| --- | --- |
| 极大文件（> 1 GiB） | 未做流式落盘；受浏览器内存限制 |

## 七、手工验收清单（可选，供人工复核）

1. 用真实浏览器打开 `http://127.0.0.1:5188/`
2. 拖入一张真实照片 → 选择 3 层算法（含 SM4）→ 开始加密
3. 确认密钥弹窗出现，红色警告可见，密钥默认选中
4. 直接点「我已复制，关闭并销毁」→ **必须**出现二次确认
5. 点「取消」→ 弹窗仍在，密钥仍可复制
6. 复制 Hex → 关闭 → 确认弹窗消失
7. 打开 DevTools → Application → 检查 Local Storage / Session Storage / Cookies / IndexedDB
   → **不应出现任何 32 位 Hex 串**
8. 刷新页面 → 页面中不再出现该密钥
9. 下载 `.XUQIAN` 文件，新建标签页重新打开网站（模拟"换设备"）
10. 在解密页粘贴密钥 → 拖入 `.XUQIAN` → 解密 → 与原文件比对哈希
11. 故意改一位密钥 → 应提示"密钥错误或文件损坏"
12. 用文本编辑器打开 `.XUQIAN` 文件 → 头部可读，但**看不出任何密钥信息**
13. 缩小浏览器到手机宽度 → 布局不错乱、无横向滚动
